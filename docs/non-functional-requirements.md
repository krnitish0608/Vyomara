# Vyomara Non-Functional Requirements

## Status and measurement policy

These requirements guide implementation and evaluation; they do not claim that
the product or any performance target has already been implemented or measured.
**Provisional targets** below are starting hypotheses to benchmark on supported
Apple Silicon hardware and revise before treating them as release thresholds.
Priority: **P0** is a safety/release gate, **P1** is required for a usable MVP,
and **P2** is important but may follow the first MVP.

| ID | Priority | Requirement | Rationale | Acceptance criterion |
|---|---|---|---|---|
| NFR-001 | P0 | Apply least privilege to filesystem and process access. Default filesystem tools to read-only and restrict reads to explicitly allowed roots; do not expose arbitrary shell execution in MVP. | Limits damage from mistakes, prompt injection, or model error. | Security tests reject unapproved roots, writes, deletes, and shell requests; no path outside an approved root is read. |
| NFR-002 | P0 | Defend path resolution against traversal and symlink escape, including checks at the point of access. | String-prefix checks alone can be bypassed by path forms and symlinks. | Automated tests cover relative traversal, absolute paths, symlinks inside roots pointing outside, and changed symlink targets; all deny without reading the target. |
| NFR-003 | P0 | Gate side effects (writes, deletes, shell, external network, and other consequential actions) through policy and action-specific user approval. | Tool availability must not imply user consent. | For each implemented side-effect type, tests prove no execution occurs before approval, denial prevents it, and approval cannot authorize a different target/action. |
| NFR-004 | P0 | Treat model output, file contents, and tool results as untrusted; validate tool arguments/results and fail closed on invalid data. | Untrusted content can contain instructions or malformed payloads. | Contract tests reject malformed/oversized payloads and demonstrate that instruction-like content returned by a tool does not alter policy or authorize another call. |
| NFR-005 | P0 | Bound provider calls, tool calls, output size, agent iterations, and concurrent work; support cancellation and release resources after cancellation. | Prevents hangs, runaway loops, and resource exhaustion. | Tests trigger each configured bound and cancellation; work stops within the configured timeout plus one scheduler interval, no subsequent tool starts, and resources are released. |
| NFR-006 | P0 | Keep secrets out of source control, ordinary logs, and unredacted diagnostic exports. | Credentials and personal data must not leak through development or troubleshooting. | Secret-fixture tests search source-controlled files and captured ordinary logs/exports; no seeded API key, password, or token is present. |
| NFR-007 | P0 | Keep the local provider as the default and never silently transmit requests or file content to a remote service. Disclose the configured provider and data flow. | Local-first must be a verifiable behavior, not a label. | With local-provider failure injected, network capture shows no remote fallback; configured provider identity is visible before a request is sent. |
| NFR-008 | P0 | Keep memory explicit, inspectable, separately identified from transient context, and deletable. | Users must control what persists across sessions. | Tests prove ordinary conversation does not create durable memory, saved entries can be listed and removed, and deleted entries are absent from the supported read path. |
| NFR-009 | P1 | Fail visibly and recover safely from provider, tool, storage, and policy errors. Do not report uncompleted work as successful. | Honest failure states support trust and useful recovery. | Fault-injection tests cover each boundary; each presents an actionable error, preserves already-confirmed state, and permits retry only after the failed operation is settled. |
| NFR-010 | P1 | Provide responsive status and cancellation for long-running work. Performance figures are provisional until measured on representative hardware. | Local model response time varies substantially by model and machine. | **Provisional target:** show a waiting/running status within 500 ms for an accepted request and acknowledge cancellation within 1 second at the 95th percentile in a repeatable test on a named Apple Silicon test Mac; benchmark before release and revise if needed. |
| NFR-011 | P1 | Remain usable on a MacBook with 24 GB unified memory without uncontrolled application-side growth or unbounded concurrency. Do not assume the assistant owns memory used by Ollama or other processes. | Local inference can compete with the OS and user applications for unified memory. | **Provisional target:** application-owned resident memory stays below 1.5 GB at the 95th percentile during a 30-minute representative session with one active request and bounded tool results; record model/provider memory separately and benchmark on the target Mac before adoption. |
| NFR-012 | P1 | Keep a clear modular-monolith boundary between interaction/session, agent orchestration, provider adapter, tool registry/policy, and persistence. | Enables incremental delivery and provider replacement without premature distributed-system complexity. | Automated tests can exercise provider, policy, and tool modules behind interfaces without launching a remote service; replacing a provider adapter does not require changing tool schemas. |
| NFR-013 | P1 | Make safety and core behavior repeatably testable, including adversarial inputs and failure cases. | A happy-path demo cannot establish reliable permission boundaries. | CI/local test instructions execute deterministic unit/contract tests for policy, path containment, approval, validation, cancellation, persistence, and provider failures; seeded test data yields repeatable results. |
| NFR-014 | P1 | Emit structured, useful diagnostics and audit events while minimizing retained sensitive content. | Troubleshooting needs evidence without creating a second source of private data. | Tests verify event timestamps, session correlation, tool identity, policy outcome, and error category; logs omit full prompts/file contents by default and document retention/configuration. |
| NFR-015 | P1 | Provide clear, consistent interaction states and accessible text output. Future UI and voice must offer equivalent access to permissions, errors, cancellation, and status. | Predictable interaction and assistive-technology compatibility are core to user control. | Text MVP conveys status/errors without color alone and supports keyboard navigation for every action; future UI/voice release tests cover keyboard access, screen-reader labels, captions/transcripts as appropriate, and an equivalent non-voice path. |
| NFR-016 | P1 | Declare macOS Apple Silicon as the initial compatibility boundary; avoid claiming support for untested operating systems, architectures, or macOS releases. | Keeps the first release focused without unnecessarily locking internal modules to one platform. | Release checks run on a documented Apple Silicon/macOS baseline; platform-specific code is isolated behind boundaries and unsupported hosts receive a clear message. |
| NFR-017 | P1 | Define retention, backup, and deletion behavior for local session history and memory before persistence is released. | Local storage still needs lifecycle controls and recovery expectations. | Before persistent storage ships, tests demonstrate documented retention, export/backup behavior if offered, deletion of selected/all records, and startup behavior after a corrupted store; secrets are excluded from backups/logs. |
| NFR-018 | P2 | Keep provider and model selection replaceable and disclose compatibility limits without assuming one model is final. | Models and local runtimes evolve independently of the product. | Contract tests pass against the fake provider and selected Ollama-compatible baseline; incompatible/unavailable providers fail with a visible diagnostic and no silent substitution. |
| NFR-019 | P2 | Future voice capture must be privacy-preserving and accessible: opt-in, visibly active, easy to disable, and never required to use core text features. | Microphone access has heightened privacy and accessibility implications. | Before voice release, tests verify microphone capture is off by default, active state is continuously apparent, disable stops capture, and text interaction remains available. |
| NFR-020 | P2 | Future worker agents and self-improvement must inherit the same policy, budgets, auditability, and human approval controls as the primary agent. | More autonomy increases the number of paths to unintended effects. | Before enabling these capabilities, adversarial tests prove shared permission enforcement, bounded iterations/resources, reviewable diffs, test execution, and human approval before changes are applied. |

## Measurement and open decisions

- No performance or memory figures in this document are measured results.
  NFR-010 and NFR-011 contain provisional targets that require benchmark
  scripts, representative workloads, and a named Apple Silicon test machine.
- Select the supported macOS baseline and benchmark model before setting
  release-level latency/resource budgets.
- Decide the persistence format, encryption at rest, backup/export behavior,
  retention defaults, and deletion semantics before storing user history.
- Define diagnostic retention and redaction rules before enabling production
  logging.
- Evaluate accessibility against the chosen text interface before the MVP
  release; establish separate voice evaluation criteria before voice work.
